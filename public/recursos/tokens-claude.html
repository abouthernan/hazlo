Categoría 01
Manejo de archivos
Cómo preparar tus archivos antes de trabajar con Claude para consumir la menor cantidad de tokens posible. Pequeños cambios, grandes ahorros.
Tip 01 · 📁 Archivos

Convierte archivos antes de subirlos

✗ Lo que sueles hacer
Subir contrato.pdf directamente → 3.000 tokens consumidos por página
✓ Lo que deberías hacer
Copiar el texto, guardarlo como contrato.md y subir ese → solo 200 tokens
📊 Una página de PDF = 1.500–3.000 tokens. El mismo archivo en markdown = menos de 200. Es una diferencia de hasta 15×.
Tip 02 · 📁 Archivos

No subas toda tu carpeta

✗ Lo que sueles hacer
Subir toda la carpeta del proyecto cuando solo necesitas revisar un archivo
✓ Lo que deberías hacer
Subir solo el archivo que Claude necesita para esa tarea específica
📊 Incluso 1 token extra se acumula. Si repites el error en 10 sesiones al día, el costo es real. Menos archivos = menor costo siempre.
🧠
Categoría 02
Gestión de contexto
El contexto acumulado es el mayor consumidor de tokens. Aprender a gestionarlo puede reducir tu consumo hasta en un 88%.
Tip 03 · 🧠 Contexto

Resume cada 15–20 mensajes

✗ Lo que sueles hacer
Seguir en el mismo chat de 30 mensajes — el 88.5% de tokens se va en historial
✓ Lo que deberías hacer
"Resume todo en bullets." → copias el resumen → abres chat nuevo
📊 Un desarrollador midió su uso: el 88.5% de los tokens están en el historial. Solo el 11.5% es contenido nuevo. El historial es el enemigo silencioso.
Tip 04 · 🧠 Contexto

Nuevo tema = nuevo chat

✗ Lo que sueles hacer
En el chat de un proyecto preguntar sobre otro tema — Claude arrastra contexto irrelevante
✓ Lo que deberías hacer
Abrir chat nuevo para cada tema — contexto limpio, sin peso extra
📊 Cada mensaje nuevo carga todo el historial anterior. Si el tema cambió, ese contexto solo suma costo sin aportar valor.
Tip 05 · 🧠 Contexto

Pon lo importante al final del prompt

✗ Lo que sueles hacer
"Eres experto en marketing, llevas 10 años... [tarea al inicio] ...tono directo"
✓ Lo que deberías hacer
"Eres experto en marketing LATAM, tono directo. Escribe un asunto de email."
📊 Claude tiene un recency bias — presta más atención a lo que está al final del prompt. Pon la tarea principal siempre al cierre.
Tip 06 · 🧠 Contexto

Reinicia, no hagas seguimiento

✗ Lo que sueles hacer
"No, eso está mal, inténtalo de nuevo" — Claude relee 20 mensajes anteriores ≈ 105K tokens
✓ Lo que deberías hacer
Editar el mensaje donde Claude se equivocó → regenerar desde ahí ≈ 2.500 tokens
📊 Una sesión de 25 mensajes consume ~105.000 tokens. Una de 3 mensajes = ~2.500. La diferencia es de 42×.

Categoría 03
Cómo escribir el prompt
La forma en que escribes tus prompts determina cuántos tokens gastas en correcciones y en outputs innecesariamente largos.
Tip 07 · ✍️ Prompting

Agrupa tareas en un solo mensaje

✗ Lo que sueles hacer
Msg 1: "Resume esto" → Msg 2: "Dame 3 puntos clave" → Msg 3: "Sugiere un título" = 3 recargas de contexto
✓ Lo que deberías hacer
"Resume este texto, dame 3 puntos clave y sugiere un título." = 1 sola recarga
📊 Cada mensaje recarga el contexto completo. 3 mensajes = 3 recargas. Agrupar tareas es absolutamente gratis.
Tip 08 · ✍️ Prompting

Pide el formato de salida explícito

✗ Lo que sueles hacer
"Dame ideas para el post de LinkedIn" → Claude responde con 3 párrafos, intro, conclusión... tokens extra
✓ Lo que deberías hacer
"Dame 5 ideas para LinkedIn. Solo el hook, máximo 10 palabras cada uno."
📊 Sin instrucciones de formato, Claude siempre produce más de lo necesario. Define el output desde el inicio y ahorra en cada respuesta.
Tip 09 · ✍️ Prompting

Di qué NO hacer desde el inicio

✗ Lo que sueles hacer
Claude entrega texto con introducción larga → corriges → más tokens gastados en la corrección
✓ Lo que deberías hacer
Desde el inicio: "Sin introducción, sin conclusión, sin frases como 'Claro, aquí tienes...'"
📊 Corregir después de recibir el resultado cuesta el doble: el error + la corrección. Las restricciones negativas son gratis.
Tip 10 — Avanzado · ✍️ Prompting

Separa el rol del contenido con Proyectos

✗ Lo que sueles hacer
Cada chat nuevo: "Eres copywriter experto en LATAM, tono directo..." = tokens repetidos en cada sesión
✓ Lo que deberías hacer
En el system prompt del Proyecto defines el rol una sola vez → Claude lo tiene siempre, cacheado
📊 Anthropic confirmó: el contenido en el system prompt de Proyectos no se contabiliza igual que el contexto del chat. Es la forma más eficiente de reutilizar instrucciones.
